# เสียงปุ่มเมนู — คัดไว้แล้ว ยังไม่ได้ต่อเข้าเกม

คัดจาก Kenney `ui-audio` + `interface-sounds` (CC0) วัดคลื่นแล้วเลือกมา 7 ไฟล์
**เก็บไว้ที่นี่เพราะยังไม่ได้ใช้** — ไม่ได้อยู่ใน `MAP` ของ `build_sfx.py`
จึงยังไม่ถูกแปลงลง `assets/` และยังไม่กินเน็ตของคนเล่น

| ไฟล์ | ยาว | ศูนย์ถ่วง | เอาไว้ทำ |
|---|---|---|---|
| `click2.ogg` | 45 ms | 2855 Hz | กดปุ่มทั่วไป (มีเนื้อ เบส 31%) |
| `click4.ogg` | 27 ms | 4203 Hz | กดปุ่มทั่วไป แบบคมกว่า |
| `rollover2.ogg` | 32 ms | 2264 Hz | เลื่อนผ่านปุ่ม (เดสก์ท็อปเท่านั้น) |
| `select_001.ogg` | 40 ms | 3182 Hz | เลือกตัวละคร |
| `select_002.ogg` | 40 ms | 2635 Hz | เลือกตัวละคร (อีกเสียง) |
| `back_002.ogg` | 60 ms | 1246 Hz | ย้อนกลับ ต่ำกว่าเสียงเลือก = ทิศทางตรงข้าม |
| `confirmation_001.ogg` | 280 ms | 401 Hz | กดเริ่มเกม |

## ที่ยังไม่ได้ต่อ ไม่ใช่เพราะลืม

เมนูเป็น **DOM ล้วน ๆ** (`index.html` + แผงเลือกตัวใน `ScrambleScene`)
ไม่ได้ผ่าน Phaser และไม่ได้ผ่านลูปอีเวนต์ของซิม
`SFX.bank` กับ `_sfx()` ใช้ `this.sound` ของฉาก ซึ่งหน้าเมนูยังไม่มีฉาก
ต้องมีทางเล่นเสียงฝั่ง DOM แยกต่างหาก (`new Audio()` หรือ AudioContext ของตัวเอง)
เป็นงานคนละระบบกับที่ทำไปแล้ว ไม่ใช่การเติมไฟล์เพิ่ม

## สามเรื่องที่ต้องคิดตอนทำ

1. **นโยบาย autoplay** เสียงแรกต้องเกิดจากการกดของคนจริง ปุ่มแรกที่กดจะเงียบเสมอ
   ถ้าไม่ปลดล็อก AudioContext ไว้ก่อน
2. **ปุ่มปิดเสียงต้องคุมอันนี้ด้วย** ตอนนี้ `sfr.muted` อ่านจากฝั่งฉาก
   ถ้าเมนูไม่อ่านค่าเดียวกัน คนที่ปิดเสียงไว้จะยังโดนเสียงปุ่มเด้งใส่
3. **`rollover` ใส่เฉพาะเดสก์ท็อป** บนมือถือไม่มี hover จริง
   ถ้าผูกกับ pointerover มันจะดังตอนแตะ ซ้ำกับเสียงคลิกพอดี
