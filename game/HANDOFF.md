**ปัญหาที่เจอ:** แมพ `neon_underline_bangkok` (และแมพ 3 ชั้นในอนาคต) ตัวละครสูงเกินไปจนชนชั้นบน (`_checkLadderEntry`/headroom ที่คำนวณไว้ตอนออกแบบยังไม่พอ เมื่อทดสอบจริงบนขนาดตัวละครเต็ม 100%)

**แนวทางที่คิดไว้:** ทำเป็น **mode แยก** สำหรับเล่นบนแมพแบบ platform (ไม่กระทบแมพ flat เดิม/ไม่กระทบขนาด-สปีดตัวละครปกติ):
- ลดขนาดตัวละครลงเหลือ **60%**
- ลดสปีดวิ่งลง
- ตัดปุ่ม dash (ดับเบิลแท็ปทิศเดิม = วิ่งเร็ว) ออกไปเลยในโหมดนี้
- ลดระยะ double jump ลง
- กล้องยังคง "lock ทั้งความสูง world" แบบเดิม (ไม่ใช่ scroll ตามตัวละคร) — ดู `_setupCamera`/zoom = 720/worldHeight ที่คุยกันไว้ก่อนหน้า

**บล็อกแมพใหม่ที่อยากได้ — ไม่มีจุดตกตายอีกต่อไป (ตัด `level.pits`/fall hazard ออกทั้งหมด):**
- ยังเป็น 3 ชั้น บน/กลาง/ล่าง เหมือนเดิม ใช้พื้นที่จอให้คุ้มที่สุด (เต็มความกว้าง/สูงจอ) · ขึ้น-ลงทุกจุดผ่าน**บันไดปีน**เท่านั้น (ระบบ `Player.startClimb`/`level.ladders` ที่มีอยู่แล้ว ใช้ซ้ำได้เลย)
  - **ชั้นล่างสุด**: พื้น flat เต็มความกว้างจอ ไม่มีช่องว่าง/หลุมเลย (เดินได้สุดขอบซ้ายขวา ไม่มีทางตก) มีบันไดขึ้นชั้นกลาง **2 บันได ชิดขอบซ้าย-ขวา**
  - **ชั้นกลาง**: พื้น flat เต็มความกว้างจอเหมือนกัน มีบันไดขึ้นชั้นบนสุด **1 บันได อยู่กึ่งกลาง**
  - **ชั้นบนสุด**: พื้น flat แต่เป็นแพลตฟอร์ม**ลอยตรงกลาง**เท่านั้น (ไม่เต็มความกว้าง) — ซ้าย-ขวาของแพลตฟอร์มนี้เป็นที่ว่าง ให้กระโดด/ตกลงไปชั้นกลางได้ (ใช้เป็นทางหนีตอนสู้บนสุด ไม่ใช่ fall hazard เพราะชั้นกลางรองรับอยู่ — ไม่มีจุดใดในแมพนี้ที่ตกแล้วตาย/เสีย stock)
  - ข้อความผู้ใช้ขาดตอนท้าย: "จุดเชื่อมระหว่างชั้นล่าง..." — ยังไม่ได้ระบุจบว่าจุดเชื่อมระหว่างชั้นล่างกับอะไร/เงื่อนไขอะไร (ตอนทำจริงตีความว่าหมายถึงบันได 2 จุดริมซ้าย-ขวาที่ระบุไว้ในบรรทัดเดียวกันแล้ว — ถ้าไม่ตรงกับที่ตั้งใจไว้ แก้ `sakura-heights.js` ได้เลย ไม่กระทบเอนจิ้น)

**ยังไม่ตัดสินใจตอนจดไว้ (ตอนนี้ตัดสินใจแล้วตาม changelog ด้านบน):** ตัวเลขจริงของ speed/double-jump ที่ลดลง (78%/82%), เลือกโหมดจากล็อบบี้ใหม่ (`LobbyScene.js`) แทนปุ่ม M เดิม, `level.pits` ตัดออกทั้งหมดในแมพใหม่โดยทำเป็นแมพที่ 2 แยกไปเลย (`sakura-heights.js`) ไม่ได้แก้ `neon_underline_bangkok` เดิม

## เกมคืออะไร

2D side-view party brawler เล่นกับเพื่อนในออฟฟิศ (เทส local ก่อน → LAN 4 คนทีหลัง)
สไตล์อ้างอิง: Stick Fight / Duck Game — มันส์ วุ่นวาย เล่นง่าย จบไว · Phaser 3 (CDN 3.70) + ES modules

**รันเกม:** แตก zip → `cd game` → `npx serve` → เปิด localhost:3000
**ห้ามเปิด index.html ตรง ๆ** (ES module โดน CORS บล็อกเมื่อเปิดแบบ file://)

## ระบบที่เสร็จแล้ว

**Combat**
- ปุ่มตี = ต่อยธรรมดาซ้ำ (สลับภาพหมัด 1/2/3 แต่ดาเมจใช้หมัดแรกเสมอ)
- **สกิล 1 = คอมโบรัว** (หมัด 3 จังหวะ + ไม้ตาย) · สกิล 2/3 เปิดเมื่อร่าง/อาวุธ/คลาสประกาศ def (`isSkillEnabled`) — `Player.SKILL_ENABLED` เป็นค่าเก่าไม่มีใครใช้
- v26: สกิลใช้ค่าที่ resolve ตามตัวละครแล้ว (`damageMul` คูณ `damagePerHit`/`finalDamage` ด้วย → **สกิลของ KunJae เบาลงจากเดิม** 3→2 ต่อฮิต, ฮิตปิด 8→5) · เช็ค "เป็นสกิลไหม" ด้วย `name` แทนการเทียบ object
- hitbox/hurtbox, hitstun, knockback, ประกาย, กล้องสั่น · ค่ากลางอยู่ `combat.config.js`
- **ค่าต่อตัวละคร:** `CHARACTER_COMBAT` เป็นตัวคูณทับค่ากลาง ผ่าน `resolveAttack(spec, key)` · key มาจาก `animPrefix` อัตโนมัติ
- hitbox = `standingHeight * 0.26` กว้าง, `* 0.95` สูง — ยังเป็นค่าประมาณ

**Hitstop (v26)** — หยุดภาพทั้งจอตอนหมัดเข้า · ค่าอยู่ `HITSTOP` ใน `combat.config.js`

| กรณี | ms | ≈ เฟรม |
|---|---|---|
| หมัดปกติ | 50 | 3 |
| หมัดปิดชุดไม้ตาย | **150** | 9 |
| ฮิตย่อยไม้ตาย (9 ฮิตห่าง 55ms) | 16 | 1 — ยาวกว่านี้ท่าจะยืดจนเสียจังหวะ |
| หมัดที่โดนกัน | 33 | 2 |
| การ์ดแตก | **180** | 11 |

- `scene.hitstop(ms)` เรียกซ้อนได้ (ใช้ค่ายาวสุด) · หยุด physics / animation (global) / tween / `scene.time` · กล้องสั่นกับ particle ฤดูยังเล่นต่อ
- `update()` นับ hitstop **ก่อน**เช็ค gameOver (หมัดปิดเกมจะได้ปลดภาพ) · `create()` เรียก `anims.resumeAll()` กันค้างถ้ากด R ระหว่างภาพหยุด (AnimationManager เป็นของทั้งเกม)
- knockback ที่ตั้งก่อนหยุดยังอยู่ ปล่อยภาพแล้วกระเด็นต่อทันที
- ประกายตอนโดนกัน = วงฟ้าเล็ก (แยกจากหมัดเข้า)

**กัน (block)** — ปุ่ม S กดค้าง
- เฉพาะตอนยืนพื้นและไม่ได้ตี/โดนตี/ยั่ว · ดาเมจเหลือ 25% (`BLOCK_DAMAGE_MUL`) knockback 35% · ไม่เข้า hitstun
- ตัวที่ไม่มีเฟรม `block` กดแล้วไม่เกิดอะไร (ตอนนี้ KunJae ไม่มี)
- หักดาเมจที่ `MainGameScene._applyDamage(victim, damage, blocked)` — `blocked` มาจาก CombatSystem ที่จำไว้**ก่อน** `applyHit` (หมัดที่ทำให้การ์ดแตกยังนับเป็นหมัดที่กันได้)

**Guard break (v26)** — แก้ "ยืนกันอย่างเดียวไม่มีทางแพ้" · ค่าอยู่ `GUARD` ใน `combat.config.js` · เลือกทางนี้แทนท่าจับทุ่มเพราะไม่ต้องมีอาร์ตใหม่
- มาตร `player.guard` 0-100: กันค้างเสีย 12/วิ · โดนตีตอนกันเสีย 14 + ดาเมจดิบ → **หมัดปกติ 5 หมัดติดแตก** / **กันค้างเฉย ๆ แตกใน ~8 วิ**
- ปล่อยปุ่มกัน 0.7 วิแล้วค่อยฟื้น 25/วิ
- แตก = state `guardbreak` ยืนแข็ง 1.1 วิ (ใช้เฟรม hurt + กระพริบ) · hitstop 150 · กล้องสั่น · เสียงต่ำ · ป้าย "GUARD BREAK!" เหนือหัว
- โดนตีระหว่างแตก: แข็งต่ออย่างน้อยเท่าเวลาที่เหลือ (หมัดเบาไม่ช่วยให้หลุดเร็ว) · หายแข็งแล้วมาตรกลับมา 50%
- `isStunned()` รวม `guardbreak` แล้ว → ทุกจุดที่ห้ามทำท่าตอนโดนตี ห้ามตอนการ์ดแตกด้วยอัตโนมัติ
- หลอดการ์ดเล็กเหนือหัว (`_drawGuardBars`) โชว์เฉพาะตอนกันหรือมาตรไม่เต็ม · ฟ้า → ส้ม (<50%) → แดง (<25%)
- เกิดใหม่ = มาตรเต็ม
- NPC สุ่มกันอยู่แล้ว (18%) → ตีรัว ๆ จะเห็นการ์ดแตกได้เลย

## ⚠️ กับดักที่เคยเจอ — อย่าพลาดซ้ำ

**ตรวจ syntax ต้องใช้ module mode** — `node --check ไฟล์.js` ตรวจไม่เจอ (script mode) เคยจอฟ้าเพราะ `_createTauntButtons` ขาดปีกกาปิด:
```bash
cd game
for f in $(find src -name "*.js"); do
  cp "$f" /tmp/chk.mjs
  node --check /tmp/chk.mjs || echo "พังที่ $f"
done
```

**เช็คชื่อเฟรมใน JS ต้องมีใน atlas** — ชื่อผิดไม่ error ตอนโหลด แต่ตัวละครจะหายตอนเล่นท่านั้น → `node tools/tests/frames.test.mjs`

**แทรกโค้ดด้วยการตัดสตริงช่วง [start:end] ต้องเช็คว่า start < end** — เคยทำให้เมธอดใน scene ซ้ำทั้งชุด (JS ไม่ error ตัวหลังทับตัวแรกเงียบ ๆ) → `frames.test.mjs` ตรวจเมธอดซ้ำให้แล้ว

**ไฟล์ใน outputs ที่สร้างไว้รอบก่อนอาจเขียนทับไม่ได้** (เจ้าของคนละ user) — เช็คจำนวนเฟรม/เวลาไฟล์หลังบันทึก ถ้าไม่เปลี่ยนให้ใช้ชื่อใหม่

**stub ใน `tools/tests` ต้องมีตำแหน่ง body ตามตัวจริง** — เดิม `body.x` คงที่ 0 ทำให้ hitbox ที่ควรโดนไม่โดน (และที่ไม่ควรโดนก็ผ่าน)

**ParticleEmitter: ใช้ `emitParticle(n)` ไม่ใช่ `explode(n)`** ถ้าจะปล่อยก้อนแรกแล้วปล่อยต่อเนื่อง — `explode()` สลับ emitter เป็นโหมดยิงครั้งเดียว

**atlas ห้ามกว้างเกินลิมิต texture** — แถวเดียวยาวเกิน 16384 (บางเครื่อง 8192) = ตัวละครเป็นกล่องดำ · สคริปต์ build เก่า (kunjae/dearv2/marchv2) ยังแพ็คแถวเดียว ต้องรัน `tools/repack_atlas.py` ต่อทุกครั้ง (`build_oat.py` แพ็คหลายแถวในตัวแล้ว)
```bash
python3 -c "
from PIL import Image; import glob
for f in sorted(glob.glob('assets/characters/*_atlas.png')):
    w,h=Image.open(f).size
    print(f, w, h, '❌' if max(w,h)>8192 else '')"
```

**ปุ่มบนจอ (Shape) ต้องระบุ hit area เอง** — `setInteractive({useHandCursor:true})` ทำ `create()` พัง:
```js
.setInteractive(new Phaser.Geom.Circle(R, R, R), Phaser.Geom.Circle.Contains)
```

**`setFrame()` รับอาเรย์ไม่ได้** — `anim()` รับได้ แต่ constructor ต้องหยิบเฟรมแรกเอง

**ตัวจมพื้นตอน spawn ครั้งแรก** — แก้แล้วด้วย `body.updateBounds()` ใน `applySpriteScale()` + `placeFeetAt()` อ่าน `body.sourceHeight` · อย่าลบสองจุดนี้

**ตัดเฟรมจากวิดีโอ**
- **ไล่ดู contact sheet เองทุกครั้ง** อย่าเชื่อตารางช่วงเฟรมที่จดมา (ของ OAT คลาดไปหลายช่วง)
- **หาจังหวะหมัดจากความกว้างตัวต่อเฟรม** (จุดยอด = แขนยืดสุด) แล้วซูมดูว่าแขนไหน · มุม 3/4 หันขวา: เปิดอก = แขนหน้า, บิดตัวเห็นหลังโค้ท = แขนหลัง
- **เช็คการต่อท่าด้วยภาพซ้อน** (เฟรมท้ายท่าก่อน = แดง, เฟรมแรกท่าถัดไป = น้ำเงิน) — เห็นทันทีว่าตัวกระตุกไหม
- เก็บชิ้นใหญ่สุดชิ้นเดียว ไม่งั้นเงาพื้นติดมา → ระดับเท้าเพี้ยน ท่ากระโดดไม่ดูลอย
- ถมรูเฉพาะที่ไม่ใช่พื้นขาว (ช่องระหว่างขา/โค้ท)
- อย่าเอาช่วง "ออกตัว" มาลูป
- หารอบก้าวจากความกว้างต่อเฟรม: กว้างสุด 2 จุดที่ขาเดียวกันนำ = 1 รอบ
- ฝุ่นที่แตะเท้าจะติดมากับตัว → เลือกเฟรมก่อนฝุ่นขึ้น
- ตัดสินคุณภาพที่ขนาดจริงในเกม ~190px บนพื้นเข้ม
- เอฟเฟกต์ขาวบนพื้นขาว (ควัน/ไอ/แสง/น้ำแข็ง) ตัดได้ด้วยการเทียบกับพื้นหลังเปล่า — ดู `cutout_fx` ใน `build_oat_titan.py`
- สั่งคลิปใหม่ย้ำ "full body always inside the frame" — คลิปไททันหัวหลุดขอบตอนกระโดด

**อาร์ตผ่านในแชท ≠ อยู่ในเกม** — ต้องประกอบ atlas + แก้ FRAME ใน JS + เพิ่มใน `roster.js`
