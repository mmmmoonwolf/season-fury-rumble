# เล่นข้ามเครื่อง (netplay) — สิ่งที่รู้จากการเล่นจริง

> **สถานะ: เล่นได้แล้ว** ทดสอบจริง iPhone 11 (host) กับ iPhone 17 Pro Max
> เจอสองบั๊ก แก้แล้วทั้งคู่ · ยังมีข้อจำกัดเรื่องหน่วงที่ยังไม่แก้ (ดูท้ายไฟล์)

วิธีทำงานอยู่ใน `src/modes/scramble/netplay.js` — lockstep แบบหน่วงอินพุต ส่งแค่ปุ่มที่กด

## บั๊กที่ 1 · เกมวิ่งเร็วเกิน

**อาการที่ผู้เล่นเจอ**: "ภาพวิ่งกันเร็วมากๆ เหมือนกดคูณ 3"

`tickNet()` เขียนไว้ว่า:

```js
let budget = 4;                                  // เผื่อไว้ตอนไล่ตามหลัง
while (budget-- > 0 && this.net.ready()) { ... }
```

เจตนาคือ "เผื่อไว้ตอนตามหลัง" **แต่ lockstep จองอินพุตล่วงหน้า `delay` เฟรมอยู่แล้วทั้งสองฝั่ง**
(`pushLocal` เติมคิวถึง `frame + delay`) `ready()` จึงเป็นจริงติดกัน `delay + 1` เฟรม **ตลอดเวลา**
ไม่ใช่แค่ตอนตามหลัง

`update()` มี accumulator คุมให้ `tick()` มา 60 ครั้ง/วินาทีอยู่แล้ว
เดินซิม 4 เฟรมต่อ tick จึงแปลว่าซิมวิ่งเกินความเร็วจริง — **วัดในเทสต์ได้ 2 เท่าพอดี**
(ไม่ถึง 4 เท่าเพราะยังถูก `ready()` คุมอยู่บางจังหวะ)

**ไม่เกี่ยวกับรีเฟรชเรตของจอ** — iPhone 17 Pro Max 120 Hz กับ iPhone 11 60 Hz
ได้ tick 60 ครั้ง/วินาทีเท่ากันเพราะ accumulator แปลง delta เป็นเฟรมให้ บั๊กนี้เกิดกับทุกคู่เครื่อง

### ทางแก้

เดินหนึ่งเฟรมต่อ tick เป็นหลัก เดินเกินได้เฉพาะตอน **ตามหลังจริง**
คือคิวของอีกฝั่งกองไว้เกินระยะจองล่วงหน้า:

```js
const lead = this.net.behind - (this.net.delay + 1);   // หักระยะจองที่มีอยู่ตลอดเวลาออกก่อน
let budget = 1 + Math.max(0, Math.min(NET_CATCHUP, lead));
```

ไม่หัก `delay + 1` ออก ทุก tick จะดูเหมือนตามหลังอยู่เสมอ แล้วเร่งทิ้งทุก tick

## บั๊กที่ 2 · เอฟเฟคค้างบนจอ กองสะสม

**อาการที่ผู้เล่นเจอ**: "effect ฟันค้าง ไม่หายไปจากหน้าจอ ยิ่งเอฟเฟคเพิ่มมากเท่าไรยิ่งค้างสะสม"

`tick()` ขึ้นต้นด้วย:

```js
tick() {
  if (this.net) { this.tickNet(); return; }    // <-- ทุกอย่างใต้นี้ไม่ทำงานตอนต่อเน็ต
```

ใต้บรรทัดนั้นมีทั้งการแปลอีเวนต์เป็นภาพ/เสียง **และตัวนับอายุอนุภาค** (`_stepFx`)
ขณะที่ **รอยฟาดถูกยิงจาก `draw()`** (`slashFor` ใน `_drawCharSprite`) ซึ่งทำงานอยู่ตลอด

= มีคนสร้างอนุภาค แต่ไม่มีใครนับอายุ → ค้างบนจอไปเรื่อย ๆ ไม่มีวันหาย ยิ่งตียิ่งสะสม

### ทางแก้: แยก `tick()` เป็นสามส่วน

| ส่วน | เรียกเมื่อไหร่ | ทำอะไร |
|---|---|---|
| เดินซิม | ต่อ tick | ออฟไลน์เดินเอง · ต่อเน็ตเดินผ่าน `tickNet()` |
| `_simEvents()` | **ต่อหนึ่งเฟรมของซิม** | แปลอีเวนต์เป็นป้ายเลข เสียง จอสั่น อนุภาค |
| `_ageFx()` | ต่อ tick | นับอายุอนุภาค ประกาย ป้ายเลข |

`_simEvents()` ต้องเรียกต่อ **หนึ่งเฟรมของซิม** ไม่ใช่ต่อ tick เพราะ `sim.events` ถูกล้างทุก `step()`
tick ที่ไล่ตามหลังแล้วเดินสามเฟรม ถ้าเรียกท้าย tick จะเหลืออีเวนต์เฟรมสุดท้ายเฟรมเดียว
ป้ายเลขดาเมจจะหายไปสองในสาม

**ของแถม**: ตอนต่อเน็ตเพิ่งมีป้ายเลขดาเมจ เสียง และจอสั่นเป็นครั้งแรก (เดิมไม่มีเลย)

## ทำไมเทสต์ 1233 ข้อเดิมจับไม่ได้ทั้งสองอัน

เทสต์ netplay เดิมถามว่า **"สองเครื่องเห็นตรงกันไหม"** ซึ่งตอบว่าตรง และตรงจริง

มันตั้งใจไล่เดินให้เร็วที่สุดเพื่อเทียบสถานะ — `while (lsA.ready() && lsB.ready())` ไม่มีเพดาน
**คำถามว่า "เดินเร็วเท่าที่ควรไหม" ไม่มีใครเคยถาม** และ `tickNet()` (ซึ่งเป็นที่ที่บั๊กอยู่)
ไม่เคยถูกเทสต์เลยแม้แต่ครั้งเดียว — เทสต์เรียก `Lockstep` ตรง ๆ ข้าม `tickNet` ไป

ทำนองเดียวกัน ไม่มีเทสต์ไหนถามว่า "ตอนต่อเน็ต โค้ดฝั่งภาพถูกเรียกครบไหม"

`tick_rate.test.mjs` ถามสองข้อนั้นตรง ๆ และ **ลองใส่บั๊กเดิมกลับเข้าไปแล้วทั้งคู่**:
`budget = 4` → ฟ้องสามข้อ (โชว์ 240 เฟรมใน 120 tick) · `return` → ฟ้องว่านับอายุ 0/5 ครั้ง

## ข้อจำกัดที่ยังไม่แก้: หน่วงมากกว่าระยะจอง = เกมเดินช้ากว่าเวลาจริง

lockstep เดินเฟรม F ได้ก็ต่อเมื่ออินพุตเฟรม F ของอีกฝั่งมาถึง
อีกฝั่งส่งเฟรม F ตอนมันอยู่เฟรม `F - delay` แล้วใช้เวลาเดินทาง `lag`

**ถ้า `lag > delay` เกมจะเดินช้ากว่าเวลาจริงโดยหลีกเลี่ยงไม่ได้** ราว `delay / (lag + delay)`
วัดจากเทสต์ (`delay` = 3):

| หน่วงทางเดียว | ความเร็วที่ได้ |
|---|---|
| 1 เฟรม (~17 ms) | 99% |
| 3 เฟรม (~50 ms) | 79% |
| 6 เฟรม (~100 ms) | 48% |

100 ms ทางเดียวเป็นเรื่องปกติของเน็ตมือถือ ถ้าเจอ **อาการจะเป็น "ช้าและกระตุก" ไม่ใช่เร็ว**

**ทางแก้ที่ยังไม่ได้ทำ**: ปรับ `delay` ตามหน่วงที่วัดได้จริง (แลกกับปุ่มหน่วงขึ้น)
`delay` เป็นค่าของแต่ละเครื่องล้วน ไม่ได้เข้าไปในซิม จึงปรับได้ฝ่ายเดียวโดยไม่ต้องตกลงกับอีกฝั่ง
และไม่กระทบ desync เลย

**เร่งให้เดินเกินหนึ่งเฟรมต่อ tick ไม่ใช่ทางแก้** — มันคือบั๊กที่ 1 นั่นเอง
แก้อาการช้าได้จริงแต่แลกด้วยเกมวิ่งเร็วเกินตอนเน็ตดี ทั้งคู่คือความเร็วผิด

## วิธีตรวจตอนเทสจริง

กด **F** (หรือปุ่ม `Hz`) เปิดตัววัด — กดได้ตอนต่อเน็ตแล้ว โชว์สามค่า:

```
จอวาด 60/วิ · เกมเดิน 60 เฟรม/วิ · ความเร็ว 1.00x
```

- **ความเร็ว ≈ 1.00x** = ถูก · มากกว่า = บั๊กแบบที่ 1 กลับมา · น้อยกว่า = หน่วงเกินระยะจอง
- **จอวาด** บอกรีเฟรชเรตจริงของเครื่องนั้น (120 บน ProMotion) ซึ่งไม่ควรมีผลกับ "เกมเดิน"
