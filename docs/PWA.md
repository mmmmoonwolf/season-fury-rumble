# ติดไอคอนหน้าจอ / เล่นตอนไม่มีเน็ต

`manifest.webmanifest` + `sw.js` + `assets/icons/`

## ไอคอนทำจากตัวละครจริง

ครอปเฟรม `idle_1.png` ของ Nyx จากอัตลาสจริง ตัดขอบโปร่งออก แล้ววางกลางพื้นสี `#0f172a`
(สีเดียวกับ `backgroundColor` ของเกม) ออกมาสี่ขนาด: 192 · 512 · 180 (iOS) · 32 (favicon)

ทำจากอัตลาสตรง ๆ แปลว่า**เปลี่ยนอาร์ตตัวละครแล้วสร้างไอคอนใหม่ได้ทันที**ไม่ต้องวาดแยก

ประกาศ 512 ไว้สองรอบ อันหนึ่งเป็น `maskable` — ไม่มีอันนั้น Android จะตัดขอบเป็นวงกลมทับตัวละคร

## iOS ไม่อ่าน manifest ต้องบอกแยกทุกอย่าง

`apple-touch-icon` · `apple-mobile-web-app-capable` · `apple-mobile-web-app-status-bar-style`

ไม่มีสามบรรทัดนี้ ไอคอนบนโฮมสกรีนจะเป็นภาพหน้าเว็บย่อ และเปิดแล้วยังมีแถบที่อยู่ของ Safari
ทับอยู่ ซึ่งกินพื้นที่จอแนวนอนไปมาก

## สองชั้น กลยุทธ์คนละแบบ

| ชั้น | อะไรบ้าง | กลยุทธ์ |
|---|---|---|
| เปลือก | html · js · vendor · ไอคอน (~2 MB) | **มีเน็ตเอาของใหม่เสมอ** ไม่มีเน็ตค่อยใช้แคช |
| ของหนัก | `assets/` (~38 MB) | มีในแคชใช้เลย ไม่มีค่อยโหลดแล้วเก็บ |

### ทำไมเปลือกเป็น network-first ไม่ใช่ cache-first

เกมนี้ deploy แล้วเทสบนมือถือจริงทุกครั้ง **ถ้าเสิร์ฟของเก่าก่อน คนเทสจะเปิดมาเจอบิลด์เมื่อวาน
แล้วรายงานบั๊กที่แก้ไปแล้ว** เสียเวลาสองฝั่งและไล่ไม่เจอว่าทำไมแก้แล้วยังเป็น

ข้อเสียคือไม่ได้ความเร็วตอนเปิด แต่โหลดจาก GitHub Pages ก็เร็วพออยู่แล้ว
**สิ่งที่ PWA ให้จริงในเกมนี้คือเปิดเล่นได้ตอนไม่มีเน็ต ไม่ใช่เปิดเร็วขึ้น**

อาร์ต 30 MB จึงไม่โหลดล่วงหน้า — เล่นตัวไหนไปแล้ว ตัวนั้นเล่นออฟไลน์ได้

## ห้าข้อที่กัน "พังแล้วพังถาวร"

service worker ที่เขียนผิดอยู่ระหว่างผู้ใช้กับเซิร์ฟเวอร์ เสิร์ฟของเก่าค้างได้ตลอดกาล
และผู้ใช้แก้เองไม่ได้นอกจากล้างข้อมูลเว็บทิ้ง ซึ่งไม่มีใครรู้ว่าต้องทำ
`pwa.test.mjs` จึงเน้นข้อพวกนี้มากกว่าเน้นว่าทำงานถูก:

1. **แตะเฉพาะ GET ของโดเมนตัวเอง** — สัญญาณต่อห้องของ PeerJS เป็นการเชื่อมต่อข้ามโดเมน
   เข้าไปยุ่งเมื่อไหร่ต่อห้องพังทันที (ลองถอดบรรทัดนี้ออกแล้ว เทสต์ฟ้อง)
2. **ไม่เก็บคำตอบที่ใช้ไม่ได้** — เก็บ 404 หรือ opaque ไว้แล้วจะเสิร์ฟของเสียซ้ำ ๆ ตลอดไป
3. **`skipWaiting` + `clients.claim`** — ตัวใหม่เข้าแทนทันที ไม่ต้องรอปิดทุกแท็บ
4. **ลบแคชเวอร์ชันเก่าตอน activate** — ไม่งั้นพื้นที่บวมขึ้นทุกครั้งที่ deploy
5. **ไม่ใช้ `addAll`** — มันล้มทั้งก้อนถ้ามีไฟล์เดียวพลาด แล้วผู้ใช้จะไม่มี service worker เลย
   ซึ่งแย่กว่ามีแบบที่ขาดไปหนึ่งไฟล์ · โหลดทีละไฟล์แล้ว `catch` ทีละอันแทน

เทสต์ยังเช็คด้วยว่า **โมดูล `.js` ทุกไฟล์ใน `src/` อยู่ในรายการโหลดล่วงหน้า** —
ลืมไฟล์เดียวแปลว่าเปิดออฟไลน์แล้วจอขาว ซึ่งรู้ตัวตอนไม่มีเน็ตแล้วเท่านั้น
(ลองถอด `uisfx.js` ออกแล้ว เทสต์บอกชื่อไฟล์ให้เลย)

## ลงทะเบียนแบบที่พังแล้วไม่ลามไปที่เกม

อยู่นอก `type="module"` ตั้งใจ — เบราว์เซอร์เก่าจนโหลด module ไม่ได้ อย่างน้อยไอคอนยังทำงาน
เช็คว่ารองรับก่อน · ไม่ลงทะเบียนตอนเปิดจากไฟล์ตรง ๆ · path relative ทั้งหมด
(GitHub Pages เสิร์ฟจากโฟลเดอร์ย่อย ใส่ `/` นำหน้าเมื่อไหร่ก็หลุดไปรากโดเมน) · ห่อ try ทั้งก้อน

## เวลาปล่อยเวอร์ชันใหม่

เปลือกเป็น network-first อยู่แล้ว โค้ดใหม่ถึงมือคนเล่นทันทีโดยไม่ต้องทำอะไร
**เปลี่ยน `VERSION` ใน `sw.js` เฉพาะตอนที่ไฟล์ใน `assets/` เปลี่ยน** (อาร์ตหรือเสียงใหม่)
เพราะชั้นนั้นเป็น cache-first ไม่งั้นคนที่เคยเล่นจะเห็นอาร์ตเก่าค้าง
