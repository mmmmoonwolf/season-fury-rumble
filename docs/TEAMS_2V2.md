# 4 คน 2v2 — แผนและข้อตกลง

> **สถานะ: C1 · C2 · C3 · C4 เสร็จแล้ว — กดเล่น 2v2 เครื่องเดียวได้จากในเกมแล้ว**
> (คนจริง 2 + AI 2) เหลือ A · B ถึงจะเล่น 2v2 ข้ามเน็ตได้

## ทำไมทีมง่ายกว่าฟรีสำหรับออล

ตอนคุยกันเรื่อง 3 คนแบบฟรีสำหรับออล มีคำถามค้างสามข้อที่ตอบยาก
พอเปลี่ยนเป็น **2v2 ทีมตอบให้เองทั้งสามข้อ**

| คำถาม | คำตอบที่ทีมให้ |
|---|---|
| ท่าที่เล็งใส่ "คู่ต่อสู้" จะเล็งใคร | **ศัตรูที่ใกล้ที่สุด** — นิยามชัด คิดจากระยะล้วน ไม่มีสุ่ม |
| แพ้ชนะยังไง | ทีมไหนล้มครบทั้งคู่ = เสียยก ใช้ `ROUND_BARS = 3` เดิมได้ |
| เวทีแน่นไหม | 4 ตัว × กว้าง 44 = 176 px ในพื้นที่เล่น 1200 px — ไม่แน่น |

## ข้อตกลงที่ตัดสินแล้ว

### ตีโดนเพื่อนร่วมทีม: แยกสองประเภท

| ประเภท | เพื่อนร่วมทีมโดนไหม |
|---|---|
| **ท่าที่เล็งใส่คน** (หมัด แส้ กระสุน) | **ไม่โดนเลย ทะลุผ่าน** |
| **ของที่วางไว้ในโลก** (ไห ไฟ ระเบิด หมอก) | **โดนแรงกระแทก แต่ไม่เสียเลือด** |

**เหตุผลที่แยก** — ท่าเล็งคือสิ่งที่คุณ *เลือกจะชี้ใส่ใคร* ชี้ใส่เพื่อนก็ควรไม่เกิดอะไร
แย็บพลาดแล้วไปขัดคอมโบเพื่อนคือความทรมานที่ไม่ได้เพิ่มอะไรให้เกม
ส่วนของที่วางในโลกคือ **โลกที่ผลักทุกคน** ไม่เลือกหน้า

และมันเก็บตัวตนของ Momus ไว้ครบ — คุณยังเขี่ยเพื่อนตกเวทีด้วยระเบิดตัวเองได้ แค่ไม่ได้ฆ่าเขา
**กติกานี้คือการขยายของที่มีอยู่แล้ว** ไม่ใช่ของใหม่: `blast()` ทำ "เจ้าของโดนแรงกระแทก
ไม่เสียเลือด" อยู่แล้ว แค่ขยายจาก "เจ้าของ" เป็น "ทีมเดียวกัน"

### คนที่ถูกน็อกกลางยก

รอจนจบยก ไม่เกิดใหม่ — ตรงกับระบบยกเดิมที่สุด และทำให้ "เหลือคนเดียวสู้สองคน" เป็นสถานการณ์
ที่เกิดขึ้นจริงและพลิกได้ ซึ่งเป็นช่วงเวลาที่สนุกที่สุดของเกมทีม

## ก้อนงาน

| | ก้อน | สถานะ |
|---|---|---|
| **C1** | `p1`/`p2` → `fighters[]` + `team` | ✅ **เสร็จ** |
| **C2** | ระบบยก/แพ้ชนะแบบทีม + ตีกันทุกคู่ | ✅ **เสร็จ** |
| **C3** | HUD 4 หลอด + แผงเลือกตัว 4 ช่อง + โหมดในเมนู | ✅ **เสร็จ** |
| **C4** | กติกาตีโดนเพื่อน | ✅ **เสร็จ** |
| A | `Lockstep` N คน | รอ — เล็ก เทสต์ได้ด้วยท่อปลอม |
| B | ท่อจริง 4 คน | **รอจนกว่า 2 คนข้ามเน็ตจะเทสต์ผ่าน** |

## C1 ทำอะไรไปบ้าง

**ไม่เปลี่ยนพฤติกรรมอะไรเลย** เทสต์เดิม 1060 ข้อผ่านครบหลังแก้ ซึ่งเป็นเงื่อนไขที่ตั้งไว้แต่แรก
ถ้าข้อไหนแดงแปลว่ารื้อผิด

- `Game.fighters` เป็นลิสต์ · **`p1`/`p2` ยังเรียกได้ผ่าน getter**
  โค้ดเดิมกว่าร้อยจุดจึงไม่ต้องแก้พร้อมกันทีเดียว ซึ่งเป็นวิธีเดียวที่รีแฟคเตอร์ขนาดนี้
  จะตรวจสอบได้ว่าไม่ได้เปลี่ยนอะไร
- `Fighter.team` — 1v1 ได้ทีม 0 กับ 1 อัตโนมัติจากไอดี โหมดเดิมจึงไม่ต้องแก้ที่เรียก
- `foe()` → **ศัตรูที่ใกล้ที่สุด** · 2 คนได้ผลเหมือนเดิมเป๊ะ
- `foes()` / `sameTeam()` ใหม่
- `blast()` · `updateBoxes()` · `resetPositions()` วนลิสต์จริงแล้ว ไม่ใช่ `[p1, p2]` ตายตัว

### จุดที่ต้องระวังและเขียนเทสต์ล็อกไว้แล้ว

**ระยะเท่ากันเป๊ะต้องเลือกตัวเดิมเสมอ** เกิดได้จริงตอนเริ่มยกที่จุดเกิดสมมาตร
ถ้าสองเครื่องตัดสินไม่เหมือนกัน ท่าวาร์ปจะพาคนละทางแล้วภาพหลุดกันทันทีโดยไม่มีอะไรฟ้อง
จึงตัดสินเสมอด้วยลำดับในลิสต์ **ไม่ใช้ `sort`** เพราะไม่รับประกันความเสถียรเท่ากันทุกเอนจิ้น

**`blast()` เคยเขียน `[this.p1, this.p2]` ตายตัว** ถ้าลืมแก้ คนที่สามกับสี่จะยืนกลางระเบิด
แล้วไม่เป็นอะไรเลย — บั๊กที่มองไม่เห็นจนกว่าจะมีคนเล่นสี่คนจริง มีเทสต์ยืนสี่คนกองกันแล้ว
ระเบิดต้องโดนสามคน (ทุกคนยกเว้นเจ้าของ)

## C2 · C4 ทำอะไรไปบ้าง

### `step()` เดินทุกคน และตัดสินการชนทุกคู่

เดิมตัดสินแค่ `resolveHit(p, d)` กับ `resolveHit(d, p)` **ถ้าลืมแก้ คนที่สามกับสี่จะตีใครไม่โดนเลย
และไม่มีใครตีเขาโดน** ซึ่งดูเหมือนเกมค้างมากกว่าบั๊ก

ตอนนี้วนทุกคู่ทั้งสองทิศ — 2 คนได้ 2 คู่เหมือนเดิม 4 คนได้ 12 คู่
**เรียงตามลำดับในลิสต์เสมอ ไม่ใช่ตามใครตีก่อน** สองเครื่องจึงตัดสินลำดับเดียวกัน

`step()` รับอินพุตเป็น rest parameter แล้ว โค้ดเดิมที่เรียก `step(a, b)` ยังใช้ได้เหมือนเดิม

### ยกจบเมื่อ "ทั้งทีม" ล้ม

1v1 คือทีมละคน จึงได้ผลเหมือนเดิมเป๊ะ — มีเทสต์ล็อกข้อนี้ไว้ต่างหาก

### สามจุดที่เคยเขียนว่า "อีกคนนึง" และจะเล็งผิดตัวทั้งหมดเมื่อมีสี่คน

| เดิม | อาการถ้าลืมแก้ |
|---|---|
| `sh.owner === 'p1' ? this.p2 : this.p1` (กระสุน) | กระสุนของคนที่สามจะไปเล็ง p1 เสมอ **แม้ p1 จะเป็นพวกเดียวกัน** |
| `fire.owner === 'p1' ? this.p2 : this.p1` (กองไฟ) | ไฟตอดได้ทีละคนเดียว และอาจตอดผิดคน |
| `[this.p1, this.p2]` ใน `blast()` | คนที่สามกับสี่ยืนกลางระเบิดแล้วไม่เป็นอะไร |

ทั้งสามจุด**มองไม่เห็นเลยตอนเล่นสองคน** จึงเขียนเทสต์สี่คนจับไว้ทุกจุด

### กติกาตีโดนเพื่อน — ทำตามที่ตกลงไว้

- `resolveHit()` ขึ้นต้นด้วย `if (this.sameTeam(a, d)) return;` → **ทะลุเพื่อนไปเลย
  ไม่เจ็บ ไม่ขัดจังหวะ และนับเป็นตีพลาด** (`hitConfirmed` ไม่ติด) ซึ่งสำคัญ
  เพราะท่าที่ต่อคอมโบด้วย `onHit` จะได้ไม่ต่อจากการตีโดนเพื่อน
- `blast()` เช็คจาก **ทีมของเจ้าของ** ไม่ใช่ไอดีเจ้าของ → เพื่อนโดนแรงกระแทกแต่ไม่เสียเลือด
- กองไฟข้ามพวกเดียวกัน · กระสุนเล็งเฉพาะศัตรู

## C3 ทำอะไรไปบ้าง

กดเล่นได้จริงแล้ว: ปุ่ม **2v2 (คนจริง 2 + AI 2)** ในแผงเลือกตัว

### จัดวงใหม่ตอนกดเปลี่ยนโหมด ไม่ใช่ตอนกดเริ่ม

`Game.setRoster(2 | 4)` สร้างลิสต์ใหม่ทั้งชุด **แต่เก็บตัวละครที่เลือกไว้ของสองคนแรก**
เพราะลำดับที่เกิดขึ้นจริงคือ "เลือกตัวเสร็จแล้วค่อยกดเปลี่ยนโหมด" — ถ้าล้างทิ้ง
คนเล่นต้องเลือกใหม่ทุกรอบโดยไม่รู้ว่าทำไม

จัดวงตอนกดเปลี่ยนโหมด ไม่ใช่ตอนกดเริ่ม แผงเลือกตัวจึงโชว์ครบสี่ช่องทันที

### จุดที่เขียนว่า "สองคน" ไว้ในฝั่งภาพ และคนที่สามสี่จะหายไปเฉย ๆ

| เดิม | อาการถ้าลืมแก้ |
|---|---|
| `for (const f of [s.p2, s.p1])` (ลูปวาดตัวละคร) | **คนที่สามกับสี่ล่องหนทั้งเกม** |
| `(s.p1.x + s.p2.x) / 2` (พารัลแลกซ์) | ฉากหลังเลื่อนสวนกับคนที่สามสี่ |
| `[s.p1, s.p2]` (ฮิตบ็อกซ์ · แถบท่าตั้งป้อม · เช็คติดกรง) | ท่าของคนที่สามสี่ไม่มีเอฟเฟกต์ |
| `s.p2.comboHits` (ตัวนับคอมโบ) | ตีคนที่สี่แล้วตัวเลขไม่ขึ้น |
| `5 - (f.id === 'p1' ? 0 : 1)` (ความลึกสไปรท์) | สามคนได้ความลึกเท่ากัน สลับหน้าหลังมั่วทุกเฟรม |
| `controlDummy` เล็ง `this.p1` | **เพื่อน AI ของทีม 0 ยืนหันหลังให้ศัตรูตลอดเกม** |

ทั้งหมดมองไม่เห็นเลยตอนเล่นสองคน

### HUD

หลอดเลือดจับกลุ่มตามทีม ฝั่งละคอลัมน์ — ทีมละคนได้หลอดสูง 12px เหมือนเดิมเป๊ะ
ทีมละสองคนหดเหลือ 7px ซ้อนกัน แล้วขีดหลอดยกเลื่อนลง 14px ไม่ให้ทับ

(1v1 ยังเรียกชื่อตัวละครเหมือนเดิม เพราะ "ทีม 1 WINS" อ่านแล้วแปลกเมื่อมีคนเดียว)

### แผงเลือกตัว

ช่องถูกสร้างจาก `fighters` จริง ไม่ใช่สองช่องตายตัวใน HTML — 2 คนได้ 2 ช่อง 4 คนได้ 4 ช่อง
เข้าคอลัมน์ตาม**ทีม** ไม่ใช่ตามลำดับในลิสต์ (ลิสต์เรียงสลับทีม ถ้าเอาเข้าดื้อ ๆ
เพื่อนร่วมทีมจะไปอยู่คนละฝั่งจอ)

ความถูกต้องย้ายจาก HTML ไปอยู่ในโค้ดที่รันตอนกดปุ่ม ซึ่งอ่านจากไฟล์ไม่เห็น
จึงมี `select_panel.test.mjs` ที่รันแผงจริงบน DOM ปลอมขนาดจิ๋ว
