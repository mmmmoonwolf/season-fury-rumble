## ขาวดำบนพื้นดำ แล้วย้อมสีเอา

อาร์ตสั่งมาเป็น **ขาวดำล้วนบนพื้นดำสนิท** ซึ่งแปลงเป็นเท็กซ์เจอร์ได้โดย**ไม่ต้องคีย์สีเลยสักขั้นตอน**
(ต่างจากอาร์ตตัวละครทุกตัวที่ต้องเขียนตัวตัดพื้นเฉพาะตัว — Alecto ใช้พื้นที่หมวก · Atlas ใช้
ขอบ+ความสว่าง · Momus ใช้พื้นที่ตัว)

**ความสว่าง = ความทึบ** ส่วน RGB ทิ้งไปเป็นขาวล้วน เพราะชุดนี้ต้องใช้ได้ทั้งสองโหมดผสม:

| โหมด | ใช้กับ | ทำไม |
|---|---|---|
| `ADD` (ค่าเริ่มต้น) | ประกาย ไฟ แสง รอยฟาด | ขาว × สีที่ย้อม = เรืองแสง |
| `NORMAL` | **ควัน ฝุ่น** | ควันขาวในโหมด ADD บนฟ้ากลางวันจะหายสนิท |

ข้อสองเป็นกับดักที่เห็นก็ต่อเมื่อเปลี่ยนฉากเป็นกลางวันแล้วเท่านั้น

## รอยฟาดผูกกับ "ชื่อท่า" ไม่ใช่ต่อตัวละคร

ทุกตัวใช้ชื่อท่าเดียวกันหมด (`jab1`/`side`/`up`/…) `SLASH_DEFAULT` ตารางเดียวจึงครอบทั้งโรสเตอร์
ตัวที่อาวุธต่างจริงค่อยเขียนทับใน `CHAR_ART[x].slash`

**Alecto เขียนทับทั้งชุด** — แส้ยาวกว่าอาวุธอื่นทั้งโรสเตอร์ ต้องเป็นเส้นสะบัดยาว ไม่ใช่รอยดาบโค้ง
และ **ท่าปืนตั้งเป็น `null` ทุกท่า** — ปืนไม่ได้ฟาด มันยิง กระสุนเป็นตัวบอกอยู่แล้ว

### ขนาดรอยฟาดยึดความกว้าง hitbox จริง

```js
const reach = hb ? hb.w : 90;
scale: (reach / src.width) * 1.15
```

**รอยที่ใหญ่กว่าระยะที่โดนจริงคือการโกหกคนเล่น** เขาจะอ่านระยะผิดทุกครั้งที่เห็น
และมันปรับตัวเองตามท่า: จิ้มสั้นได้รอยสั้น แส้ยาวได้รอยยาว โดยไม่ต้องจูนทีละท่า

### ปล่อยเฟรมเดียวต่อหนึ่งท่า

ปล่อยที่ **เฟรมแรกของช่วง `active`** เท่านั้น
- ปล่อยทุกเฟรมที่ยังอยู่ในท่า → ซ้อนกันเป็นแผ่นทึบ
- ปล่อยตอนเริ่มท่า → มาก่อนกรอบโจมตีจริง ซึ่ง**สอนคนเล่นผิด**ว่าโดนได้ตั้งแต่ตอนเงื้อ

## ระเบิดประกายตอนหมัดเข้า

ทุกตัวเลขคูณตามน้ำหนักหมัด (`hitstop`) ไม่ใช่ค่าคงที่ — หมัดจิ้มกับไม้จบจึงต่างกัน**ทั้งภาพ**
ไม่ใช่ต่างแค่เวลาที่ภาพหยุด (`w = min(2.2, hs/5)` · 3 เฟรม → 0.6 · 16 เฟรม → 2.2)

## สองกับดักที่เจอตอนต่อ

**1 · ชื่อเมธอด `fx` ชนกับ `this.fx`**
`this.fx` เป็นอ็อบเจกต์ `graphics` ที่ตั้งไว้ใน `create()` อยู่แล้ว
เมธอดที่ชื่อซ้ำกับพรอเพอร์ตี้ของอินสแตนซ์จะถูก**ทับเงียบ ๆ** แล้วพังตอนรันเท่านั้น
(`this.fx is not a function`) เปลี่ยนชื่อเป็น `emit`

**2 · ADD บนฟ้าสว่างอิ่มตัวทันที**
รอบแรกตั้ง alpha 0.85 + สเกลใหญ่ + `spark()` เดิมยังยิงซ้อนอยู่ = จอขาวโพลนกลบตัวละครทั้งสองคน
แก้ด้วยการลบ `spark()` เดิมออกจาก event `hit` แล้วลด alpha ลงครึ่งหนึ่ง

## อนุภาคใช้พูลซ้ำ

`_fxPool` / `_fxLive` — หมดอายุแล้วคืนเข้าพูล ไม่สร้าง/ทิ้งอ็อบเจกต์ทุกนัด
ทั้งหมดเป็นการวาดล้วน **ใช้ `Math.random` ได้เต็มที่** เพราะ sim เดินด้วยเลขเฟรมล้วน
เอฟเฟคสองเครื่องต่างกันได้ ไม่มีผลกับผลการต่อสู้

## กล้องสองตัว: กล้องโลก / กล้อง UI

HUD เป็นอ็อบเจกต์ในโลกเหมือนตัวละคร ใช้กล้องเดียวแล้ว**ซูมทีหลอดเลือดโตตาม**
และตอนกล้องสั่น (มีอยู่แล้วทุกครั้งที่ตีหนัก) ตัวเลขบน HUD ก็สั่นไปด้วย

แยกเป็นสองตัวแล้ว:

| กล้อง | วาดอะไร | ซูม/สั่น/เลื่อน |
|---|---|---|
| `cameras.main` | ฉากหลัง พื้น แพลตฟอร์ม ตัวละคร เอฟเฟค ป้ายลอย | ได้ |
| `uiCam` | `this.hud` + ข้อความ HUD ทุกตัว | **ไม่เลย** |

**ได้ผลทันทีแม้ยังไม่มีซูม**: กล้องสั่นแล้ว HUD นิ่ง อ่านง่ายกว่าเดิม
และ HUD เกาะขอบ *จอ* ได้จริง (`this.viewW`) ไม่ใช่ขอบพื้นที่เล่น ซึ่งต่างกันตอนต่อเน็ต

### วิธีแบ่ง

เก็บลิสต์ของ UI ไว้ตอนสร้าง (`this.uiObjects` — `hud` กับทุกตัวที่ออกจากโรงงาน `T()`)
ที่เหลือใน `children.list` คือของในโลกทั้งหมด

**ไม่เดาจากชนิดหรือ depth** เพราะทั้งสองชั้นมีทั้ง graphics ทั้ง text ปนกันอยู่

### `_world()` — จุดที่พลาดแบบเงียบได้

ของที่สร้าง**หลัง** `_splitCameras()` ถูกวาดด้วยกล้องทุกตัวเป็นค่าเริ่มต้น
ลืมลงทะเบียนที่ไหน ชิ้นนั้นถูกวาดสองรอบ รอบที่สองใช้พิกัดของกล้อง UI
= เห็นเป็นภาพซ้อนเลื่อนไปอีกที่ **ซึ่งดูเหมือนบั๊กกราฟิก ไม่ใช่บั๊กกล้อง** จึงหาสาเหตุยาก

สี่จุดที่ต้องเรียก: สไปรท์ตัวละคร (`_rigFor`) · หุ่นแสดงแทน · พูลเอฟเฟค (`emit`) · ป้ายลอย (`popup`)

`ui_camera.test.mjs` มีข้อที่**ไล่ทุก `this.add.*` ในไฟล์แล้วเช็คว่าเรียก `_world` ครบ**
(เว้น `create` / `_buildStage` / `_stageScrim` ที่ทำงานก่อนแยกกล้อง)
เพิ่มของในโลกที่ไหนแล้วลืม เทสต์จะบอกชื่อเมธอดกับเลขบรรทัดให้เลย — ลองใส่บั๊กทดสอบแล้ว มันจับได้จริง

## ซูมตามตัวละคร

`_stepCamera()` — หากรอบที่ครอบทุกคน → คิดซูมที่ยังเห็นครบ → ไหลเข้าหาค่านั้น
ค่าทั้งหมดอยู่ใน `CAM` ปุ่ม **Zoom** (คีย์ `Z`) ปิดเปิดได้ กดได้ตอนต่อเน็ตด้วย

### `min = 1` เป๊ะ ไม่ใช่ต่ำกว่า

ที่ซูม 1 เวทีกว้างเท่าจอพอดีอยู่แล้ว ถอยต่ำกว่านั้นจะเห็นขอบอาร์ตฉากหลัง
จึง **ซูมเข้าได้อย่างเดียว** ซึ่งได้พฤติกรรมที่อยากได้ตรง ๆ อยู่แล้ว —
ใกล้กันซูมเข้า ห่างกันถอยมาเห็นเวทีเต็ม **และไม่ต้องแก้อาร์ตเลยสักชิ้น**

ผลพลอยได้: ปิดปุ่ม Zoom แล้วได้ภาพเดิมกลับมา**ทุกพิกเซล** เพราะที่ซูม 1
ขอบบีบกล้องจนเหลือจุดเดียว = กลางเวทีพอดี (มีเทสต์ล็อกไว้ทั้งสามความกว้างจอ)

### ถอยเร็วกว่าเข้าสามเท่า

`outLerp` 0.14 · `inLerp` 0.045 — ตั้งใจให้ไม่เท่ากัน

Nyx วาร์ป / Momus ขึ้นชั้นบนสุด ต้องเห็นเขา**ทันที** ถ้าถอยด้วยความเร็วเดียวกับที่เข้า
เขาจะอยู่นอกจอไปหลายเฟรม = **ตายเพราะมองไม่เห็น ไม่ใช่เพราะเล่นแพ้**
ซึ่งเป็นความรู้สึกที่แย่ที่สุดที่เกมต่อสู้จะให้ได้

### สามกับดัก

| กับดัก | อาการ |
|---|---|
| คิดแต่แกนนอน | Momus ขึ้นชั้นบนสุดขณะอีกคนอยู่พื้น → x ใกล้กัน กล้องซูมเข้า **คนบนชั้นหลุดขอบบนหายไปเลย** |
| นับแต่เท้า ไม่นับหัว (`headroom`) | คนกระโดดสูงหัวโดนตัดขอบบน |
| เก็บค่าที่บีบขอบแล้วไปใช้ไหลรอบหน้า | ซูมเปลี่ยน → ขอบเปลี่ยน → กล้องกระตุกเป็นก้าว ๆ (เก็บค่าดิบ บีบตอนใช้) |

### `centerOn` ไม่ใช่ `setScroll`

`scrollX` ของ Phaser ไม่คิดซูมให้ (ซูมคิดจากจุดกลางกล้อง)
เผลอใช้ `setScroll` แล้วภาพจะเยื้องทุกครั้งที่ซูมไม่เท่า 1

### netplay ไม่กระทบ

กล้อง**อ่าน** `sim.fighters` แต่ไม่เขียนอะไรกลับ sim เลย และเพราะอ่านจาก sim ที่เดินตรงกันอยู่แล้ว
สองเครื่องจึงได้กล้องตรงกันเองโดยไม่ต้องส่งอะไรเพิ่ม

`camera.test.mjs` มีข้อที่เรียกกล้อง 120 รอบแล้วเทียบสถานะ sim ทั้งก้อน — ถ้าวันหนึ่งกล้อง
เผลอเขียนอะไรกลับ sim จะโดนจับทันที (สำคัญเพราะรอบวาดของสองเครื่องไม่เท่ากัน
60 Hz กับ 120 Hz เรียกกล้องคนละจำนวนครั้งต่อเฟรม sim)
