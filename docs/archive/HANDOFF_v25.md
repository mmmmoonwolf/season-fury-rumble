## เกมคืออะไร

2D side-view party brawler เล่นกับเพื่อนในออฟฟิศ (local multiplayer ก่อน → LAN ทีหลัง)
สไตล์อ้างอิง: Stick Fight / Duck Game — มันส์ วุ่นวาย เล่นง่าย จบไว
Phaser 3, ES modules

**รันเกม:** แตก zip → `cd game` → `npx serve` → เปิด localhost:3000
**ห้ามเปิด index.html ตรงๆ** (ES module โดน CORS บล็อกเมื่อเปิดแบบ file://)

---

## ปุ่มควบคุม

- P1: ลูกศร เดิน/วิ่ง, ↑ กระโดด (double jump), Shift เดินช้า, **Space ตี**, **Enter เรียกร่าง**
- P2: WASD, W กระโดด, Ctrl เดินช้า, **G ตี**, **H เรียกร่าง**
- 1-5 สลับฤดู (particle + physics เปลี่ยน ภาพพื้นหลังใช้ภาพเดียวทุกฤดู) | F fullscreen | R เริ่มรอบใหม่ | **N ปิด/เปิดเสียง** | **V สลับตัวละคร P1, C สลับตัวละคร P2**
- **M สลับแมพ** (วนใน 3 แมพใหม่)

## ✅ ทำเสร็จแล้ว

**Tee (ตัวถัดไป) — สปาร์ตัน + ร่างสแตนด์ม่วง**
- คอนเซปต์เปลี่ยนจากเดิม (พ่อมดม่วง-เงิน) เป็น **นักรบสปาร์ตันที่เรียกร่างสแตนด์นักรบตัวใหญ่**
- **ต้องแยกจาก Bomb ให้ชัด** ไม่งั้นเป็นตัวเดียวกันคนละสกิน: ร่างของ Tee **ทึบ เรืองแสงม่วง ตัวใหญ่ ผุดข้างหลัง ต่อย/แทงเป็นเส้นตรง** ส่วนของ Bomb **โปร่งจาง ลอยข้าง ๆ ฟันกวาดเป็นเส้นโค้ง**
- prompt อยู่ใน `art_prompts_tee.md` · ระบบฝั่งโค้ดพร้อมแล้ว (`CAN_SUMMON` / `ATTACKS_VIA_SUMMON` เปิดให้ได้เลย เหลือแค่ atlas + ค่าตำแหน่ง)
- **idle ของ Tee ให้วาด 4 เฟรมโดยขยับเฉพาะผ้าคลุม** — ผ้าคลุมเป็นรูปทรงที่เปลี่ยนได้เยอะ AI วาดต่างกันชัดเจนได้ (ต่างจากการเขย่งตัวที่ล้มเหลวกับ March) ส่วนการเขย่งขึ้นลงให้โค้ดทำ

**ตัวละครแต่ละตัว = ทดสอบระบบคนละอย่าง**
- Dear = ระบบโจมตี/คอมโบพื้นฐาน · Bomb = ระบบเรียก stand · **March (ตัวถัดไป) = ทดสอบอนิเมชันเฟรมเยอะให้ลื่น**
- March: สายบู๊ระยะประชิด (close-quarters rushdown) มีชีทตัวละคร + กระดานท่าครบแล้ว รอ gen เฟรม — prompt อยู่ใน `art_prompts_march.md`
- March จะลองสไตล์ภาพใหม่แบบ "ดูมีมิติ 3D" ให้เข้ากับแมพด้วย (ถ้าเวิร์ก ค่อยพิจารณาเจนตัวเดิมใหม่ตาม)

**⚠️ Dear อัปเดตล่าสุด: idle เปลี่ยนเป็นมุม frontal (หันตรงเข้ากล้อง) + เพิ่มเฟรม stance ใหม่**
- ตามแผนเดิมทั้งโรสเตอร์ควรเป็น 3/4 (เอียง ~30°) แต่ 2 รูปที่ได้มาสำหรับ Dear เป็นมุม **frontal ตรง ๆ** ไม่ใช่ 3/4 — **ตัดสินใจแล้วว่ายอมรับมุมนี้ไปก่อน** (เข้ากับคาแรกเตอร์กวนๆ ที่จ้องตรงเข้ากล้องได้)
- **`idle.png` ถูกแทนที่แล้ว** ด้วยเวอร์ชัน frontal ใหม่ (normalize ตามธรรมเนียมเดิม: canvas 267x400, เท้าที่ y=396, สูง 393px)
- **เพิ่มเฟรม `stance.png` ใหม่** เข้า atlas แล้ว (มุม frontal เดียวกัน) — แต่ **ยังไม่ผูกเข้า state machine** ใน `Dear.js`/`Player.js` เป็นแค่เฟรมที่พร้อมใช้ ต้องเพิ่ม logic เรียกท่านี้ตอนไหน (เช่น ตอนเริ่มขยับจาก idle) ทีหลัง
**✅ Dear เป็นชุด frontal ครบทั้งตัวแล้ว — ไม่มีเฟรม side-view เหลืออยู่**
- ประกอบจากโฟลเดอร์ Google Drive (`Character Redesigned 3/4` → `DEAR`) + ชุดเจนเพิ่มรอบสุดท้าย (hurt / land / run เพิ่ม 2 เฟรม)
- **atlas ปัจจุบัน 15 เฟรม:** idle, stance, run_1-4, jump, fall, land, attack_1-3, hurt, kick, taunt
- run เต็ม 4 เฟรมแล้ว (เดิมมี 2 เฟรมกระตุก)
- **วิธี normalize:** ภาพชุด 768x1375 เจนจากกรอบเดียวกันทั้งหมด → ใช้ scale คงที่ `0.3023` ทุกเฟรมของกลุ่มนี้ **ไม่พึ่ง hair detector** เพราะค่ามันเพี้ยนข้าม batch (batch แรกจับผมได้ 116-155px, batch หลัง 158-175px ทั้งที่ภาพขนาดเท่ากัน) — ท่าติดพื้นจัดที่เท้า ท่าลอยจัดที่หัว
- **✅ `taunt` ผูกเข้าระบบแล้ว** — กด **T (P1) / Y (P2)** หรือแตะ**ปุ่มกลมบนหน้าจอ** (มุมล่างซ้าย=P1 ฟ้า, มุมล่างขวา=P2 ส้ม)
  - ท่ายั่วยืนค้าง 900ms แล้วกลับ idle เอง ระหว่างนั้น**ขยับไม่ได้ = เปิดช่องให้โดนสวน** (ราคาของท่า)
  - กดตี/กระโดดระหว่างยั่ว = ยกเลิกท่าทันที กันโดนสวนฟรี
  - **เอฟเฟกต์เขย่งหัวเราะ** ทำด้วยโค้ด บีบ-ยืดตัว (squash/stretch) เป็นจังหวะ ไม่ได้ขยับตำแหน่ง — เพราะเฟรมมีภาพเดียว และการขยับ y จะไปยุ่งกับ physics body
  - ปรับได้ที่ `Player.TAUNT_MS` (ความยาวท่า), `TAUNT_BOUNCE_MS` (ความถี่เขย่ง), `TAUNT_SQUASH` (ความแรง, 0.06 = ±6%)
  - ตัวละครที่ไม่มีเฟรม `taunt` กดแล้วไม่มีอะไรเกิดขึ้น (เช็ค `anims.exists` ก่อน ไม่พัง)
- **เฟรมที่ยังไม่ผูกเข้าระบบ:** `stance`, `kick`
- **Dear สว่างขึ้นแล้ว** — ปรับ gamma รวม 0.68 ทั้ง atlas (ยกโทนกลาง ส่วนขาวไม่หลุด)
- **ท่าที่ตัดทิ้ง:** รูป #25 ในโฟลเดอร์ Drive (ขา 3 ข้าง แขนซ้ำ)
- **หมายเหตุ:** `attack_1` ที่ใช้ตอนนี้คือรูปที่เคย reject ไปตอนทำ side-view (เหตุผลตอนนั้น: "มุมเป็น 3/4 ไม่ใช่ side-view") — พอเปลี่ยนทิศทางเป็น frontal มันกลับเข้ากันพอดี

**ตัวละคร Dear** (ตัวตลกผมส้ม ชุดขาว-แดง) — **อาร์ตครบทุกท่า ไม่มี placeholder เหลือ**
- เฟรม: idle, run_1-4, jump, fall, land, attack_1, attack_2_transition, attack_2, attack_3, hurt (13 เฟรมใน atlas)
- ท่าติดพื้น align ที่เท้า, ท่าลอย (jump/fall/hurt) align ที่หัว
- ขนาดในโลกเกม: `Dear.WORLD_HEIGHT = 180` (ปรับเพื่อแมพ sakura ที่แคบกว่าเดิม)
- P2 ใช้ sprite เดียวกัน tint ส้ม

**Combat system — เสร็จสมบูรณ์**
- คอมโบ 3 จังหวะ: ตบขวา → ตบซ้าย (มีเฟรมบิดตัวคั่น) → ตบขวาปิดชุด (หมุนกลับมุมข้าง)
- เข้าครบ 3 ครั้งจริง (ไม่ใช่แค่กด) → ปลดล็อกไม้ตาย "หมุนตบ" 9 ฮิตรัว ใช้เฟรมที่มีอยู่แล้ววนลูป ไม่ต้องวาดเพิ่ม
- hitbox/hurtbox, hitstun, knockback, ประกายตอนโดน, กล้องสั่นตอนไม้ตายจบ
- ค่าทั้งหมดจูนได้ที่ `combat.config.js` ไม่ต้องแตะ logic

**แมพ sakura-terrace** (ใช้งานจริงตอนนี้)
- ภาพระเบียงซากุระสั้นๆ ไว้เทส world 1250x698, floor y=632 (กึ่งกลางพื้นคอนกรีตในภาพ)
- พื้นแผ่นเดียวยาวเต็ม ไม่มีช่องว่าง/fall hazard เลย — ตายได้ทางเดียวคือ HP หมด (ตั้งใจ เพื่อเทสคอมโบไม่ให้ตกแมพมากวน)
- 4 จุดเกิดกระจายบนพื้น

**เสียง — เสร็จแล้ว (ข้อ 2 เดิม)**
- ตบโดน / หมัดปิดชุดไม้ตาย / เหวี่ยงมือ / กระโดด / double jump / ลงพื้น / KO
- **สังเคราะห์สดด้วย Web Audio ไม่มีไฟล์เสียงสักไฟล์** — ไม่ต้องหา asset ไม่ต้องห่วงลิขสิทธิ์ zip ไม่โตขึ้น
- ตบติดกันรัว ๆ pitch ไต่ขึ้นทีละขั้น (แบบเกมต่อสู้) เว้นเกิน 400ms รีเซ็ต
- จูนทุกค่าที่ `audio.config.js` ที่เดียว ไม่ต้องแตะ logic
- **`sfx-test.html`** = หน้าฟังเสียงทีละตัวเพื่อจูน ไม่ต้องเปิดเกมจริง (เสิร์ฟผ่าน npx serve เหมือนกัน)
- ถ้าวันหลังเจอไฟล์เสียงจริงที่ชอบ เปลี่ยนแค่ข้างใน `AudioSystem.play()` จุดเรียกใช้ในเกมไม่ต้องแก้

**ระบบตัวละครหลายตัว + Bomb (ตัวที่ 2)**
- `roster.js` เป็นทะเบียนกลาง — เพิ่มตัวละครใหม่ = สร้างไฟล์ใน entities/ (ก๊อป `Bomb.js` เป็นแบบ) แล้วใส่ 1 บรรทัด scene ไม่ต้องแก้
- animation ทุกตัวมี prefix ของตัวเอง (`dear/idle`, `bomb/idle`) — `Player.play()` เติมให้อัตโนมัติ โค้ด state ยังเรียก `play("idle")` เหมือนเดิม
- **Bomb ใช้อาร์ตจริงแล้ว** (ชุดดำ) `WORLD_HEIGHT = 190` ผืนภาพ 460x400 ตัวยืนสูง 393 เท้าที่ y=396
- ประกอบด้วย `tools/make_bomb.py` — normalize ขนาดด้วย **ขนาดหัว** ไม่ใช่ความสูง bbox (ท่าที่งอตัวจะถูกขยายจนหัวโตถ้าใช้ bbox) ท่าติดพื้นยึดเท้า ท่าลอยยึดหัว
- ไม่มีเฟรม `land` (ใช้ idle แทน) และไม่มี `attack_2_transition` (ท่าโจมตีเป็นท่าสั่งงาน ตัวไม่หมุน ไม่ต้องมีเฟรมเปลี่ยนมุม)
- ตัวแปรผู้เล่นใน scene เปลี่ยนชื่อจาก `this.bom`/`this.bomP2` → `this.p1`/`this.p2` (ชื่อเดิมสมัย placeholder ชนกับชื่อตัวละคร Bomb)
- `bomb_art_prompts.md` = ชุด prompt สั่งอาร์ต Bomb 12 เฟรม + style anchor พร้อมใช้

**ท่าเรียกร่างยมฑูต (stand) — ระบบเสร็จ อาร์ตยัง placeholder**
- Enter (P1) / H (P2) — ใช้ได้เฉพาะตัวละครที่ตั้ง `static CAN_SUMMON = true` (ตอนนี้มีแค่ Bomb)
- ร่างลอยสูงระดับไหล่ (`offsetY: -52` / ท่าฟัน -32 ถึง -54) ให้รู้สึกว่าผุดออกมาจากไหล่ ไม่ใช่ยืนอยู่ข้าง ๆ
- ไทม์ไลน์: จางเข้า 170ms → เงื้อ 90 → เหวี่ยง (hitbox เปิด) 110 → สลายขึ้นข้างบน 220 · เจ้าของท่าล็อกตัว 480ms = ราคาของท่า พลาดแล้วโดนสวนเต็ม
- คูลดาวน์ 5 วิ · HUD โชว์ ◆ = พร้อม / ◇ = ยังคูล
- ร่างไม่มี physics body ไม่ชนอะไร เป็นเอฟเฟกต์ที่ทำดาเมจล้วน ๆ — hitbox ฝากไว้กับ CombatSystem โดยผูก attacker = คนเรียก (ดาเมจเข้าบัญชีคนเรียก ไม่ต้องเช็คทีม)
- `CombatSystem.spawnHitbox()` รับ `rectProvider` เพิ่ม สำหรับ hitbox ที่ไม่ได้ติดตัวผู้โจมตี และ `feedsCombo:false` เพื่อไม่ให้ท่านี้ปลดล็อกไม้ตายฟรี
- โดนสวน/ตายกลางท่า → ร่างสลายทันที hitbox ที่ค้างเป็นโมฆะ
- **สามชั้นที่ทำให้มันอ่านเป็น "พลัง" ไม่ใช่ตัวละครอีกตัว:** อยู่สั้นมาก (<0.6 วิ) / โปร่ง 55% + ร่างซ้อนจาง 2 ชั้น + blend ADD / ไม่แตะพื้น ไม่มีเงา ลอยขึ้นลง แล้วสลายขึ้นบน
- คมเคียววาดสดด้วย Graphics ไม่ใช้ asset — เป็นส่วนเดียวที่คมชัด เพราะมันคือสิ่งที่ผู้เล่นต้องอ่านออก (= hitbox)
- **อาร์ตจริงเข้าแล้ว** — 3 เฟรม (rise / windup / swing) ผูกกับไทม์ไลน์: โผล่ = rise → เงื้อ = windup → ฟัน = swing
- ความเป็นวิญญาณ **อบไว้ในภาพ** ด้วย `tools/make_reaper.py` ไม่ใช่ทำสดในเกม: ย้อมฟ้าเทา + ไล่ความทึบตามความเข้มของเส้น (เส้น/ใบเคียวทึบกว่าผ้า) + เรืองแสงรอบตัว
  เหตุผลที่ทำนอกเกม: ทุกเฟรมจางเท่ากันเป๊ะ ถ้าให้ AI วาดจางเองจะได้คนละระดับแล้วดูกระตุก
  อยากจูนความจาง/โทนสี → แก้ `TINT` / `ALPHA_BASE` / `ALPHA_DARK` ในสคริปต์แล้วรันใหม่ (ต้องมีไฟล์ต้นฉบับ 3 ใบใน uploads)
- ทุกเฟรมยึด "หัว/ฮู้ด" ไว้ที่จุดเดียวกันบนผืนภาพ 600x480 ร่างจึงไม่กระโดดตอนสลับเฟรม
- ขนาดในเกม `worldHeight: 240` (ตัวจริงในภาพราว 88% = ~210px สูงกว่าผู้เล่น 180 พอให้ข่มแต่ไม่บังจอ)

**แมพชุดใหม่ 3 แมพ + กล้องแบบเกมต่อสู้**
- `city_night` 2048x768 · `city_dusk` 2079x756 · `river_sunset` 1983x793 — **ใช้ภาพความละเอียดต้นฉบับ 1:1** (world = ขนาดภาพเป๊ะ ไม่ย่อไม่ขยาย ภาพจึงคมสุด และไม่ต้องคำนวณ scale ระหว่างภาพกับ collision)
- ทุกแมพเป็นแนวระนาบ: พื้นเรียบแผ่นเดียวเต็มความกว้าง ไม่มีแพลตฟอร์มลอย ไม่มีที่ให้ตก ตายได้ทางเดียวคือ HP หมด
- สร้างจาก factory `flatArena()` ใน `flat-arenas.js` — เพิ่มแมพใหม่ = ใส่ภาพ + เขียน 6 บรรทัด (ขนาดภาพ + `floorY`)
- **`floorY` คือเลขเดียวที่ต้องจูน** = เส้นยืนในพิกัดภาพ ถ้าเท้าลอยหรือจมให้ขยับเลขนี้
- **กล้อง:** zoom ตั้งครั้งเดียวให้ความสูงแมพพอดีจอ แล้วไม่เปลี่ยนอีก (ขนาดตัวละครบนจอคงที่ ไม่ซูมกวนสายตา) ส่วนแนวนอนแพนตามจุดกึ่งกลางระหว่างผู้เล่นแบบหน่วง ๆ Phaser clamp ไม่ให้เลื่อนออกนอกแมพเอง
- canvas เป็น 16:9 คงที่ (1280x720) เปลี่ยนแมพไม่ต้องแก้ index.html อีกแล้ว

## 🐞 บั๊กจอฟ้าตอนเพิ่มปุ่ม taunt + KunJae (แก้แล้ว)

เปิดเกมแล้วได้จอสีกรมท่าเปล่า ๆ (`#0f172a` = สีพื้นของ Phaser) แปลว่า `create()` พังกลางทาง เจอ 2 จุด:

1. **`setInteractive({ useHandCursor: true })` บน Shape** — วงกลมที่สร้างด้วย `this.add.circle()` ไม่มี texture พอเรียกแบบนี้ Phaser จะพยายามหา hit area จาก texture แล้วพัง
   **แก้:** ระบุ geometry เอง `setInteractive(new Phaser.Geom.Circle(R, R, R), Phaser.Geom.Circle.Contains)` แล้วตั้ง `btn.input.cursor = "pointer"` แยก
   ⚠️ ถ้าจะเพิ่มปุ่มบนจออีกในอนาคต ต้องทำแบบนี้ทุกครั้ง

2. **`setFrame()` ได้รับอาเรย์** — KunJae เปลี่ยน `FRAME.idle` เป็นอาเรย์ 4 เฟรม แต่ constructor เรียก `this.setFrame(FRAME.idle)` ซึ่งรับได้เฉพาะชื่อเฟรมเดี่ยว
   **แก้:** `setFrame(Array.isArray(FRAME.idle) ? FRAME.idle[0] : FRAME.idle)` — ใส่กันไว้ทุกตัวละครแล้ว เผื่อตัวอื่นเปลี่ยนเป็นอาเรย์ทีหลัง

3. **⭐ ตัวจริงที่ทำให้จอฟ้า: `_createTauntButtons` ขาดปีกกาปิด** — ตอนแทรกเมธอดใหม่เข้าไป ปีกกาที่ปิด `_setupHud` เดิมถูกใช้ไปปิดเมธอดใหม่แทน ทั้งไฟล์เลยพังเป็น SyntaxError โมดูลโหลดไม่ขึ้นเลย = ไม่มีอะไรวาดออกจอ เหลือแต่พื้น `#0f172a`

**⚠️ วิธีตรวจที่ได้ผล (สำคัญมาก):** `node --check ไฟล์.js` **ตรวจไม่เจอ** เพราะมันตรวจแบบ script mode แต่เกมนี้เป็น ES module — ต้องก๊อปเป็น `.mjs` ก่อนถึงจะเจอ:

```bash
cd game
for f in $(find src -name "*.js"); do
  cp "$f" /tmp/chk.mjs
  node --check /tmp/chk.mjs || echo "พังที่ $f"
done
```

รันคำสั่งนี้ทุกครั้งหลังแก้โค้ด จะจับ syntax error ได้ก่อนเปิดเบราว์เซอร์

**บทเรียนอื่น:** `anim()` ใน characterAnims รับอาเรย์ได้ทุกช่อง แต่ `setFrame()` ใน constructor รับไม่ได้ — เวลาอัปเกรดท่าไหนเป็นหลายเฟรม ต้องเช็คจุดนี้ด้วยเสมอ

## 🎨 Art workflow ที่ใช้ได้ผล

gen ภาพใน Gemini → ส่งมาในแชท → ลบพื้นหลัง/สิ่งแปลกปลอม + normalize ขนาด + จัด align (เท้าหรือหัวแล้วแต่ท่าลอย/ติดพื้น) + ประกอบเป็น texture atlas (ไม่ใช่ grid sheet ธรรมดา เพราะแต่ละท่าขนาดไม่เท่ากัน) + เสียบโค้ดให้

**Style anchor ของ Dear (ใช้ซ้ำได้ทุก prompt):**
> Clean 2D anime line-art illustration style, crisp confident linework, flat-to-soft cel shading, muted naturalistic color grading. NOT painterly, NOT glossy splash art. Orthographic side view facing RIGHT, not 3/4 angle. Pure white background, no shadow. Exactly two legs and two arms clearly separated, do not overlap or duplicate limbs, anatomically correct human proportions. Same exact height as the reference. Slim young man with messy curly orange-red hair, pale white face with clown makeup and a faint red smile, tattered off-white ruffled clown costume with a large frilled collar, puffed sleeves with ruffled cuffs, dark red ribbons, red pom-poms on the chest, white bandage wraps on hands and lower legs, black lace-up boots with red pom-poms.

**บทเรียนจาก prompt ที่เจอมา:**
- ท่าตบให้ "กวนๆ" ตามคาแรกเตอร์ได้ผลดีกว่าท่าจริงจัง (ข้อมือตก, หัวเอียง, ยิ้มกวน)
- คอมโบ 3 จังหวะ ออกแบบให้หมุนมุมกล้อง (ข้าง → 3/4 → กลับข้าง) จะได้เฟรมเปลี่ยนมุมมีเหตุผลรองรับ ไม่ใช่ AI หลุดสไตล์
- ท่าที่มีเส้นความเร็ว/การหมุนอยู่แล้วในภาพเดียว เอาไปวนเป็น loop animation ได้เลยโดยไม่ต้องวาดเพิ่ม (ใช้กับท่าไม้ตายหมุนตบ)
- ท่า "landing" ยืนตรงมักได้ idle กลับมาซ้ำ — ถ้าไม่จำเป็นจริงๆ ตัดทิ้งไปเลย ใช้ idle แทนได้ ผู้เล่นแทบไม่ทันสังเกต
- สีที่ "ลอยได้เอง" (เช่น cloak แดง-ทอง) เสี่ยงชนตัวกรอง IP (โดนจับคู่กับ Doctor Strange) เปลี่ยนโทนสีหรือคำอธิบายการลอยให้เป็น "ร่ายเวท" แทน "ผ้าลอยเอง"
- ระบุ `strict side-view, only one arm visible` ทุกครั้งกันมุมกล้องหลุดเป็น 3/4 โดยไม่ตั้งใจ
- ขนาดตัวละครในเกม: อ้างอิงจาก `Dear.WORLD_HEIGHT` (ตอนนี้ 180px), วาดส่งมาที่ความสูง 1264px ขึ้นไปแล้วให้ระบบ scale ลง
